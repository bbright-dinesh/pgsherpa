Support

Help with pgSherpa for macOS.

Contact

Report a problem or ask a question by opening an issue at github.com/bbright-dinesh/pgsherpa/issues. Please include your pgSherpa version, your macOS version and your PostgreSQL version. Never include passwords, tokens or connection strings.

Getting started

  • Open the panel: click pgSherpa. Click him again to close it.
  • Add a server: the gear icon, then Servers, then Add server. A PostgreSQL role with pg_monitor is enough.
  • Run SQL: click the PSQL chip beside him. Enter after a closing semicolon runs the statement. It is read-only unless you click the read > prompt to switch to write, which asks for Touch ID or your password.
  • Bring him back or quit: the two-peaks icon in the menu bar.

Common questions

Does pgSherpa change my database?
Not unless you tell it to. Every statement runs in a read-only transaction. Writing a statement, and cancelling or terminating a session, need the SQL box switched to write: macOS asks for Touch ID or your password first, and it is back on read every time the app starts. pgSherpa's own checks never write.

Which PostgreSQL versions work?
It is tested with PostgreSQL 16 and 17, including DigitalOcean Managed Databases and Supabase. Other supported PostgreSQL versions should work; features that need a newer version say so.

Why is pg_stat_statements empty on the Activity tab?
That page reads the pg_stat_statements extension. It shows how to enable it if it is not installed, or the database's own error if the role may not read it. The other pages (pg_stat_activity, Replication, Backup) need nothing installed.

Where are my settings kept?
Only on your Mac. See the privacy policy.
